# Market setup

Share these with the partner before they start coding.

## Credentials HAAT sends to the POS

HAAT calls the partner’s APIs with:

| Header | Meaning |
| --- | --- |
| `integrator-token` | Shared for this integrator across markets |
| `organization-token` | Identifies the specific market / store |

Partner must reject requests if either header is missing or wrong (`401`).

## Credentials partner uses to call HAAT

For price sync, partner logs in and gets a bearer token:

- Username / password from HAAT onboarding  
- Then `Authorization: Bearer <token>` on sync calls  

## HAAT API environments

The following API is already available from HAAT and can be used by the POS for authentication and product synchronization.

| Environment | Base URL |
| --- | --- |
| Staging | `http://ext-integration.haat-delivery.io` |
| Production | `https://integration.internal.haat.delivery` |

## Partner POS environments

Partner POS base URL example: `https://pos.example.com` (partner chooses; share with HAAT).

## Example paths on partner POS

| Action | Example |
| --- | --- |
| Promotions | `GET https://pos.example.com/api/promotions` |
| Submit order | `POST https://pos.example.com/api/submit-order` |
| Menu build | Agreed URL or file export (same columns) |

<Tip>
  Always certify on **staging** before production.
</Tip>
