# Restaurant POS overview

HAAT calls your restaurant POS to sync the menu and create orders in real time.

## Required endpoints

<Columns cols={2}>
  <Card title="GET /api/menu" icon="book-open" horizontal>
    Full menu sync — categories, meals, deals, addons.
  </Card>
  <Card title="POST /api/orders" icon="shopping-bag" horizontal>
    Create order in POS with idempotency support.
  </Card>
</Columns>

Use the **API reference** group in this tab for full request/response schemas.

## Authentication

- `Authorization: Bearer <token>` **or** HMAC via `X-Signature`
- `X-Haat-Version: 1.0`
- On order create, honor `Idempotency-Key` (duplicates must not create duplicate orders)

## Menu sync notes

<AccordionGroup>
  <Accordion title="Performance and shape">
    - Return the **full** menu (no pagination)
    - Target response time under **5 seconds**
    - Keep `posId` values **stable** across calls
  </Accordion>
  <Accordion title="Localization and pricing">
    - Provide localized dictionaries (`en` required; `he` and `ar` recommended)
    - Price format uses decimals (e.g. `32.5`, not `3250`)
    - Addon `groupType`: `addon` (default) or `always_print`
  </Accordion>
</AccordionGroup>

HAAT syncs on initial setup, on a schedule (typically daily), on demand, and before processing orders when needed.

## Order create notes

Root fields include `orderId`, `businessId`, `customer`, `items`, `payments`, `payRestaurant`, `deliveryType` (`delivery` | `pickup`), and ISO-8601 UTC timestamps.

Respond with:

```json
{
  "status": "success",
  "message": "Order accepted",
  "posOrderId": "ORD-78456"
}
```
